# Site Design V0.1

## 1. 设计目标

这个网站应当像一个“有人生活过的地方”，而不是标准化的技术博客模板。

关键词：

- 温暖
- 安静
- 克制
- 有时间感
- 有生活痕迹
- 技术只是生活的一部分

暂定站点概念名：**留痕 / Traces**。

这只是工作名，后续可以更换。项目目录因此保持中性的 `personal-blog`。

---

## 2. 首页

首页的任务不是列出所有内容，而是让访客先感受到“这里是谁的空间”。

### 2.1 Hero

建议结构：

```text
min

留痕

记录我做过的事、想过的问题，
以及那些不值得被忘记的普通瞬间。

[ About ]  [ Archive ]
```

不放：

- Software Engineer / Researcher 等强身份标签
- GitHub contribution graph
- 技术栈 icon wall
- GPA / LeetCode / Stars 等指标

### 2.2 Now

首页保留很轻的一小块 `Now`：

```text
NOW

2026 · September

最近在学习和生活。
做一些研究，写一些代码，
也在慢慢想清楚自己以后想成为怎样的人。

→ What I'm doing now
```

完整 `/now` 页面可以记录：

- 最近在做什么
- 最近在学什么
- 最近在想什么
- 最近读什么
- 最近听什么
- 最近喜欢的一张照片 / 一件小事

旧版本不删除，未来形成时间序列：

```text
/now/2026-09
/now/2026-10
...
```

### 2.3 Recent

首页只展示少量最近内容，日期比标签更重要。

示意：

```text
RECENT

Sep 05    我为什么想拥有一个自己的博客
          Think

Sep 03    最近我在考虑读博这件事
          Think · Research

Aug 29    八月的一些事情
          Life

Aug 24    我终于真正理解 Docker 了
          Learn

→ All writings
```

分类只作为轻标签存在，不设计成传统大类导航。

### 2.4 Moments

这是整个网站最重要的内容形态之一。

```text
MOMENTS

Sep 04

今天突然决定开始认真做一个个人网站。

并不是因为我有什么一定要告诉别人的，
而是突然觉得，过去的很多想法如果没有留下来，
最后真的会像从来没有发生过一样。

· · ·

Aug 31

傍晚回去的时候天气很好。
随手拍了一张照片。

[ photo ]

→ More moments
```

Moments 默认没有标题要求。

### 2.5 Photos

照片不是摄影作品集，而是“生活证据”。

```text
PHOTOS

[ photo ] [ photo ]
[ photo ] [   photo   ]

September, 2026
一些最近留下来的生活切片。

→ Photos
```

照片允许带一句非常短的文字。

### 2.6 Projects

项目不做成简历卡片，而是讲“这个东西为什么存在”。

示意：

```text
AI Translator
我一开始只是想解决 PDF 阅读时划词翻译不够舒服的问题。
后来它慢慢变成了一个桌面工具，也让我第一次比较完整地经历了一个软件不断修修补补的过程。

Story / GitHub / Notes
```

首页只展示 2–3 个项目。

### 2.7 Currently

轻量展示当前状态：

```text
CURRENTLY

Reading     《……》
Listening   ……
Learning    Diffusion / LLM Systems
Thinking    我适不适合读博？
Building    This website
```

如果未来觉得过于模板化，可以删掉；它不是核心区块。

### 2.8 Footer

保持很轻：

```text
min · 2026

RSS   GitHub   Email

认真生活，也认真留下痕迹。
```

## 3. 文章阅读页

目标：像读一本安静的小册子，而不是 Medium / 技术文档页面。

### 3.1 顶部

```text
← Writing

我开始认真考虑读博这件事

2026 · 09 · 03
Nanjing

Think · Research
```

地点是可选字段，不强制填写。

不默认显示：

- 阅读量
- 点赞量
- 评论数
- 分享按钮墙
- 巨大的作者卡片

### 3.2 正文

阅读宽度建议约 `680–760px`。

正文允许自然混合：

- 普通段落
- 引用
- 图片
- 代码
- 少量小标题
- 脚注

技术文章也沿用同一阅读语言，不单独变成“开发者皮肤”。

### 3.3 图片

图片默认比正文稍宽，允许某些照片突破正文宽度。

图片下方 caption 更像生活注记，而不是论文图注：

```text
那天下完雨之后的校园。
```

### 3.4 文末

文章结束后不立即塞推荐列表。

可以先留一小段“这一页属于什么时候”：

```text
2026 · 09 · 03

写于一个开始认真思考未来去向的晚上。
```

然后再很轻地给：

```text
← Previous                    Next →
```

相关文章可放到更下面，且数量很少。

## 4. Moments 页面

Moments 不是微博，也不是文章列表，而是一条低压力的时间流。

### 4.1 页面结构

```text
Moments

一些不需要长成文章的东西。

2026

September

05 Sep
今天下午突然下了很大的雨……

04 Sep
[photo]
今天决定开始认真做一个个人网站。

01 Sep
最近一直在循环一首歌……

August
...
```

### 4.2 单条 Moment 能包含什么

允许：

- 一句话
- 一小段文字
- 一张或多张照片
- 一首歌 / 一本书的引用信息
- 一个链接 + 一句话
- 一个非常短的技术发现

不要求：

- 标题
- 分类
- 摘要
- SEO 描述
- 完整上下文

### 4.3 Moments 与文章的关系

Moment 可以后来“长成”文章，但不自动要求这样做。

例如：

```text
2026-09-05 Moment
“最近开始认真想自己适不适合读博。”

↓ 几周后

Essay
《我开始认真考虑读博这件事》
```

原 Moment 仍然保留，不删除，因为它记录的是当时的状态。

### 4.4 隐私边界

内容状态建议：

```text
Private → Draft → Public
```

博客只消费 `Public` 内容。

不把“公开”当作默认动作。

## 5. Archive

Archive 是网站的重要入口，因为这个网站本质上是在保存时间。

示意：

```text
Archive

2026

September
05    我为什么想拥有一个自己的博客
04    Moment · 今天突然决定……
03    最近我在考虑读博这件事

August
31    八月的一些事情
29    Moment · ...
24    我终于真正理解 Docker 了
```

文章、Moments、Logs 可以在同一条时间线上出现，通过非常轻的标识区分。

## 6. 视觉语言

### 6.1 颜色

第一版方向：

```text
Background: #F7F5F0  // 微暖纸张色
Text:       #2B2B2B  // 深灰，不用纯黑
```

强调色暂不定死。原则：低饱和、只承担少量链接/状态提示作用。

### 6.2 字体

目标不是“复古”，而是“有一点书卷感，但阅读舒服”。

- 标题：可考虑 serif
- 中文正文：优先高可读性的中文字体 fallback
- 英文/数字日期：可以与正文形成非常轻的对比

正式实现前再做字体组合测试。

### 6.3 排版

- 大量留白
- 区块之间用间距而不是卡片边框分隔
- 尽量避免圆角卡片海洋
- 尽量不用渐变、玻璃拟态、霓虹色
- 动画只用于微弱的页面进入 / hover，不抢文字和照片的注意力

### 6.4 时间表现

推荐主要日期格式：

```text
2026 · 09 · 05
```

它比 “Published on September 5, 2026” 更像一页生活记录。

---

## 7. 顶部导航

当前优先考虑：

```text
min        Archive   Projects   About
```

或者：

```text
min        Writing   Moments   Projects   About
```

最终在首页原型出来后再决定，不要同时塞：Home / Blog / Categories / Tags / Archives / Friends / Resources 等传统博客导航。

---

## 8. 内容颗粒度

不是按“技术 / 非技术”划分，而是按内容成熟度和记录目的划分：

- **Moment**：一个瞬间
- **Note**：还在生长的想法
- **Essay**：完整思考
- **Log**：一段时间的记录
- **Project Story**：一个东西从为什么开始到现在怎么样

第一版可以先不单独暴露 `Notes` 导航；它可作为内部内容类型，等真的有足够内容后再决定是否公开。

---

## 9. 明确暂不做

V0.1 不做：

- 评论系统
- 点赞系统
- 用户账户
- 花哨的 dashboard
- 复杂标签系统
- 搜索（内容少时没必要）
- 技术栈 icon wall
- 访问量展示
- 自动生成大量“猜你喜欢”

先证明最核心的三件事好用：

1. 写一篇文章很舒服。
2. 留下一条 Moment 很轻松。
3. 几个月后可以自然地按时间回看。
